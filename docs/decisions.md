# Decisions

The owner's decisions behind melies, and the choices made while porting it, with their reasons.

## At the start (owner, 27 October 2026)

1. **What melies takes over.** From `mnz-audiobook`, only the narration of one text: an optional
   title, an optional subtitle and a body, with an optional spoken notice before them. That means the
   segment plan, the WAV written as the speech comes, the single encode (standard and retail), the
   label's tags, progress and cancellation. From `mnz-trailer`, all of it.
2. **What stays in manuzio.** Reading the EPUB, building the spoken heading ("Chapter 3", "第3章") and
   the notice from its language packs, resuming across chapters (fingerprints, the parts folder), the
   ZIP and its file names, `retail-check.txt` for the whole book, preview publication, keeping the
   previous trailer until a new one succeeds (melies' render, copied from manuzio, also replaces
   `trailer.mp4` only on success), and every message users see about a book (such as
   `chapter_note`).
3. **The same output.** References recorded from manuzio's crates before any code was copied, and
   a parity test that manuzio can run after switching ([parity.md](parity.md)).
4. **The harness lives in the gitignored `tmp/harness`**, not in a workspace member: it names paths
   into the private manuzio, and the workspace must build without it.
5. **No text over the images.** manuzio's trailer README mentions it, but no code draws it, and
   `add_text` and `text` were never used by the render. melies has no such fields; manuzio's mapping
   ignores them, as its render does now.
6. **The test inputs are generated by FFmpeg**: two stills and a short Opus track, bit-exact, so no
   media is committed and manuzio's side generates the same.
7. **melies owns, besides the narration itself:**
   - the retail limits check, as typed values (`RetailProblem`); manuzio words them in its report;
   - a narration revision (`narration::REVISION`) that manuzio puts in its resume fingerprint, so a
     change in melies' plan or encode is never mixed with chapters made before it;
   - loading the voice (`Narrator::new`), with the fallback from the GPU to the CPU;
   - the ASCII file-name stems of the retail profile (`retail::ascii_stem`).
8. **Staging FFmpeg and Kokoro is Rust**, through kuleshov's `Tools::find_or_download` and kempelen's
   `assets::stage` (the `melies-stage` program), not a TypeScript script: no Bun, Biome or tsc here.
9. **Licence: CC0 1.0**, like jespersen and kuleshov. kempelen is Apache-2.0, but melies only depends
   on it and copies none of its code, which CC0 allows; a program that ships melies ships kempelen's
   NOTICE as it would anyway.
10. **Not on crates.io.** manuzio pins the repository by commit, as melies pins kuleshov and kempelen.

## While porting (27 October 2026)

11. **Synchronous**, as kempelen made synthesis: manuzio's `render_trailer` and audiobook functions
    were `async` only because loading the synthesizer was; nothing in them waited.
12. **Own input types**: `narration::Text`, `NarrationOptions`, `Profile`, `Label`;
    `trailer::Trailer`, `Step`, `Movement`, `TrailerInput`. Voices and languages are kempelen's
    (`Voice`, `Language`); the tools are kuleshov's (`Tools`). The text's first piece is the
    **title** (`SegmentKind::Title`): manuzio called it the heading, and builds it.
13. **Every function that runs FFmpeg takes `&kuleshov::Tools` first**, as kuleshov's do; the library
    reads no environment variables and finds nothing on its own. Only tests, examples and the stage
    program read `MELIES_TOOLS_DIR` and `MELIES_SPEECH_DIR`.
14. **One error type**, `melies::Error` ([errors.md](errors.md)); cancellation is always
    `Error::Cancelled`, wherever it happens.
15. **The work files keep manuzio's names** (`chapter.wav`, `segment.raw`, `trailer-work`,
    `narration-N.wav`), so FFmpeg gets the same arguments; one narration at a time per folder.
16. **`plan` applies the profile** (the retail closing pause kept within 1 to 5 seconds), so a
    caller's plan, such as manuzio's for `chapter_note`, is what is narrated.
17. **The tests keep manuzio's names**, so they can be found from manuzio's `scripts/heavy-tests.ts`
    and its history. They read the texts manuzio read for the parity cases, so no EPUB is needed here.
18. **Test tiers**: every test that needs only FFmpeg runs by default (as in kuleshov); those that
    run Kokoro are `#[ignore]`d into the model tier (as in kempelen).
19. **melies' recording shim is kuleshov's, plus WAV hashes**, so the chapter WAV, handed to FFmpeg
    in a concat list and deleted after, is compared bit for bit. kuleshov's `kuleshov-record` is a
    binary that cannot be reused from another workspace, so its fifty lines are copied; see
    [TODO.md](../TODO.md) for the change to kuleshov that would avoid the copy.
